#+title: Etmacs
#+options: toc:2

A personal, literate Emacs configuration—not a Doom or Prelude clone,
but inspired by the two. Includes Evil, discoverable leader keys, a
startup dashboard, gptel and OpenCode AI integration, vterm, Elfeed
news, mu4e support, doom-modeline, completion, Projectile/Perspective
workspaces, Treemacs, Git tools, conservative editing defaults, and
Org/roam workflows.  The source of truth and package rationales are in
[[file:config.org][config.org]]. Maintained project documentation uses Org format. Old
session/planning artifacts are not runtime dependencies and are not
part of the proposed configuration commit.

* Try without replacing your current configuration.

Requires Emacs 31.1+ with SQLite support. Run from this repository in a new
instance, not an existing server client. Nothing migrates existing notes.

1. Generate the Lisp (also provided alongside its source):
   #+begin_src sh
   emacs -Q --batch --load scripts/tangle.el
   #+end_src
2. Explicitly install third-party packages and dependencies from GNU ELPA,
   NonGNU ELPA and MELPA. This downloads and executes package code:
   #+begin_src sh
   emacs -Q --batch --load init.el --funcall et/install-packages
   #+end_src
   Or start Emacs and run =M-x et/install-packages=, then restart. Normal
   startup never refreshes archives, installs packages, or starts a graph server.
3. Start the configuration:
   #+begin_src sh
   emacs --init-directory "$PWD" --debug-init
   #+end_src
   For terminal Emacs:
   #+begin_src sh
   emacs -nw --init-directory "$PWD" --debug-init
   #+end_src

For a repeatable setup, run:
#+begin_src sh
./install.sh
#+end_src
It tangles =config.org=, installs packages into =.local/elpa=, installs the
optional parinfer-rust native library, verifies the package set, and runs the
ERT suite. Use =./install.sh --fonts= to also install the Nerd Fonts glyphs,
=--skip-parinfer= to skip the native library, or =--skip-tests= for a faster
install-only run. It never installs system packages, language servers, debug
adapters, or tree-sitter grammars.

Runtime packages and state live in ignored =.local/=. Native caches and editor
locks are not source. Packages are not version-locked; this is not a claim of
fully reproducible builds.

* Editing and local settings

Edit =config.org=, run =M-x et/tangle-config=, and restart. Do not edit generated
=early-init.el=, =init.el= or =lisp/*.el= directly. There is no auto-tangle hook
on arbitrary Org files.

Optional =.local/settings.el= loads before modules. Set =et/notes-directory=,
=et/roam-directory=, =et/default-theme=, =et/bibliography-files=, or
=et/org-extra-agenda-files= there; not every core setting is an override API.
Credentials belong in =auth-source=, normally =~/.authinfo.gpg=, not this repo.
Customize writes to =.local/custom.el= but does not automatically load it;
promote intentional shared settings into the literate source.

Custom functions *and variables* use =et/=. File and feature names retain =et-=
(for example, =et-core.el=). Update any old =et-notes-directory= or
=et-default-theme= local overrides. Restart after renaming, not hot-reloading.

Vertico handles minibuffer completion; Corfu handles in-buffer CAPFs. They do
not compete. Company/Cape are not installed without a specific need. Try Lisp
completion by typing =(messag= and pressing =C-M-i=. =TAB=/=S-TAB= move, =RET=
accepts a selected candidate, =C-g= dismisses. =C-j=/=C-k= move down/up through
Vertico, Corfu, built-in minibuffer completion, and Transient menus without
changing ordinary editing. Automatic completion begins after three characters;
CAPFs may execute Lisp, so use care with untrusted code.

GUI Vertico menus float. Terminal frames use normal minibuffer rendering;
Corfu uses supported child frames or the built-in completion fallback. In the
theme picker, =C-n=/=C-p= preview, =RET= accepts, and =C-g= restores the previous
theme. Only trusted installed theme code should be previewed. Selection is
session-only; change =et/default-theme= for a persistent default.

* Dashboard and AI

The dashboard opens on startup (=initial-buffer-choice=) and remains available at
=SPC d=. It shows Projects, Recent files, up to five Personal and five Work
tasks, Daily journal, and five cached news articles per site. Tasks are sorted
by state and explicit priority, then by deadline/schedule, with undated tasks
last; overflow is reported as =+N more=. =g= refreshes, =q= quits, =RET=
activates a button or link, and =TAB= collapses or expands the article list for
the feed at point. The News section places =Update feeds= directly beneath the
=News= heading, and each feed title has a dashed underline. =TAB= returns point
to the feed title after folding or unfolding. =SPC q= quits Emacs; =SPC R= re-tangles
=config.org= and restarts Emacs after saving buffers. Set
=et/dashboard-on-startup= to nil in =.local/settings.el= to start on scratch
instead.

=gptel= provides OpenAI, Anthropic and DeepSeek backends. API keys are read from
=~/.authinfo.gpg= through =gptel-api-key-from-auth-source= using the provider's
normal API host and auth-source user =emacs=; keys are cached for the session.
Only when no matching entry exists does Emacs prompt for another machine and
user. The global default model is =gpt-6-luna= on OpenAI. =SPC a w= rewrites the
active region with a model you choose: use it for that rewrite only, or set it
as the persistent default. The default is stored in =.local/gptel.el= and
reloaded at startup. Reasoning text is hidden by default because reasoning
tokens are billed as output.

The first AI command in a project asks for both an OpenCode model and a gptel
model. Choices are saved in =.local/project-models.el= (mode 0600) by canonical
project root; the OpenCode choice is also written to the project's root
=opencode.json= =model= key while preserving other settings. Cancelling a prompt
leaves that half unset so the next AI use asks again. Project buffers use the
saved gptel model. =SPC a l= changes only the OpenCode project model, and
=SPC p m= reconfigures both.

Both model selectors support favorites. Press =C-f= on the highlighted model to
add or remove it. Favorites are stored in =.local/model-favorites.el= (mode
0600) and appear first under a =★ Favorites= group heading, which Vertico
renders as a separator above all other models. =C-f= is bound only during these
selectors.

OpenCode sessions can be bookmarked per project. =SPC S s= (or =SPC m S= in a
session buffer) saves the current session to =.local/opencode-sessions.el= and
exports its transcript with =opencode session export= to
=.local/opencode-sessions/<id>.json= (mode 0600). =SPC S l= selects a saved
session for the current project and reopens it after restart; outside a project
it prompts for one of the saved project roots. =SPC S o= opens the live
project-session picker, and =SPC S d= removes a bookmark while keeping the
exported context. Emacs layouts and files remain separate: use =SPC TAB S= /
=SPC TAB L= for those.

=emacs-opencode= provides an OpenCode 2 client in native Emacs buffers. It is
not on MELPA, so =et/install-packages= clones it from GitHub through
=package-vc=; its =request= dependency is installed from MELPA. Git, the
=opencode= CLI, and =curl= must be available. The client uses OpenCode's shared
background service and never sends a prompt until you submit one. =SPC a o=
starts a session in the current project, =SPC a O= reopens an existing one,
=SPC a a= asks a one-shot question, and =SPC a c= includes the active region or
the lines around point. Sessions use the saved project model and prompt for a
replacement if it is no longer available. Session buffers use the client's own
=C-c C-c= (send), =C-c C-l= (model) and =C-c C-a= (agent) bindings; with Magit
loaded, =C-c C-d= shows the session's worktree diffs. Project-level
=opencode.json= sets this branch's OpenCode default to
=deepseek/deepseek-flash=; this does not change gptel's =gpt-6-luna= summary
model, and article summaries keep using that model regardless of project
choices.

** News, email and modeline

Elfeed reads Scientific American, the New York Times
Home/World/U.S./Business/Technology/Science/Health/Sports/Arts feeds, Decipher,
ArsTechnica Security, TechNet/Microsoft Security, SecurityWeek, and
BleepingComputer. A combined Emacs site reads r/emacs, Planet Emacslife, Sacha
Chua's Emacs News, Mastering Emacs, System Crafters, and Emacs Stack Exchange.
All feeds are downloaded; =SPC N s= chooses which topics feed the dashboard's
five newest articles per site. =SPC N u= updates feeds, =SPC N o=
opens Elfeed, and each site's dashboard button opens its full Elfeed search.
=TAB= in the dashboard collapses or expands the article list for the feed at
point. State lives in =.local/news.el= and =.local/elfeed/=; startup uses only
the cache.

In an Elfeed search buffer, the same leader prefix adds =SPC N /= (keyword
search), =SPC N f= (narrow to feed), =SPC N d= (date range), =SPC N m= / =SPC N M=
(mark read / unread), and =SPC N r= / =SPC N R= / =SPC N S= (download the article
and open an AI summary draft). In the dashboard, =S= summarizes the
article at point.

The summary uses =gpt-6-luna= through gptel and produces a 3–5 paragraph note.
The prompt classifies the article first. Cybersecurity articles also get
vulnerability/incident details, affected software, attack type, explicitly
reported MITRE techniques, defanged IOCs, and related
language/platform/package-manager nodes. Missing language/platform/package
nodes are created under =general/topics/= with the appropriate =:language:=,
=:platform:=, or =:package-manager:= tag. The summary links to each node and
each node gets a dated backlink under =Related articles=. Non-cybersecurity
articles contain only metadata and =* Summary=; they omit =* Security details=
entirely and are not forced to carry a security tag.

Summary tags use =_= as the only word separator; hyphens are not allowed.
Tags are prefixed by category: =#= for topics (languages, platforms, attack
types, incident types, package managers), =@= for people/groups/foundations,
=$= for companies, and =!= for explicitly reported MITRE techniques, e.g.
=#python=, =@cisa=, =$microsoft=, =!T1059=.

The summary opens in an unsaved review buffer:

| Key | Action |
|-----+---------------------------------------------------------------|
| C-c | Accept, create the node, and save it |
| C-k | Cancel and discard the draft |
| C-r | Regenerate with the current model |
| C-m | Choose a gptel provider/model and regenerate |

Nothing is written to the roam vault until =C-c=.

IOCs are defanged in the note. With point on a defanged IOC table cell, or with
a region selected, =SPC m R= refangs it and copies the result to the clipboard.

Mu4e is supported but unconfigured. Set =mu4e-maildir= (and any contexts/SMTP)
in =.local/settings.el=; =SPC M m= opens mail, =u= updates the index, =c=
composes, and =s= searches. The module adds common mu4e directories to
=load-path= and gives a clear error instead of loading a broken mail setup.

Doom Modeline supplies colors, Nerd Font icons, VC state, diagnostics, LSP,
position, and time; Minions collapses the minor-mode list. Install the icon font
once with =M-x et/install-nerd-fonts=, or set =doom-modeline-icon= to nil for a
plain terminal. The unconfigured alternative lighter options are =mood-line=,
=telephone-line=, or =nano-modeline=.

=et/meeting-mode= (toggled with =SPC P=) makes keyboard focus obvious during
screen sharing. On every focus change it briefly tints the newly focused
window, then leaves a thin theme-derived accent on its fringes, mode line, and
header line when present. It follows ordinary windows, buffer switches, the
minibuffer used by Vertico, transient menus, and frame focus changes. The accent
is regenerated when themes are enabled or disabled. Customize
=et/meeting-flash-duration=, =et/meeting-flash-alpha=, or
=et/meeting-accent-color=. The implementation is local and needs no extra
package; it is inspired by =winpulse= and =selected-window-accent-mode=.

* Projects, workspaces and windows

Projectile owns project roots/files/build/test commands; Perspective owns
workspace buffers and layouts. Same-basename projects receive distinct
=name#hash= workspaces. This is organizational isolation, not a sandbox: an
explicit file open may share a buffer between workspaces.

| Keys                    | Action                                                 |
|-------------------------+--------------------------------------------------------|
| SPC p a / SPC p p       | Register / switch project                              |
| SPC p w                 | Activate current project's workspace                   |
| SPC p f / SPC p s       | Project files / Consult project search                 |
| SPC p c / SPC p t       | Build / test (project commands may need configuration) |
| SPC p m                 | Reconfigure this project's OpenCode and gptel models   |
| SPC TAB TAB             | Numbered Vertico workspace menu                        |
| SPC TAB 1..9 / 0        | Switch directly to workspace 1..10                     |
| SPC TAB . / SPC TAB l   | Choose / previous workspace                            |
| SPC TAB a / SPC TAB d   | Add / forget a buffer, without deleting its file       |
| SPC TAB S / SPC TAB L   | Explicit session save / restore                        |
| SPC e / SPC p e         | Toggle tree / display only the current project in tree |

The mode line notification area shows every frame workspace as a numbered tab,
with the current one highlighted. `SPC TAB TAB` opens a numbered Vertico menu;
`SPC TAB <digit>` switches directly, and `SPC TAB l` returns to the previous
workspace.

Discovery is explicit, not a recursive startup scan. Treemacs uses Evil
bindings and Perspective scopes. Help opens right, compilation/warnings below;
=q= dismisses help/compilation. No additional pop-up framework is needed.

Session save/restore is *manual*. Local files and Dired layouts are supported;
remote files, tree buffers, unsaved buffer contents, terminals and LSP processes
are not restored. Unsupported windows become scratch windows. Restore only
trusted local state: opening files can invoke their mode hooks. Reconnect remote
tools deliberately. No automatic exit save can overwrite a good saved session
with a short empty session. Do not enable desktop restoration over these layouts.

* Terminal

=vterm= provides a libvterm-backed terminal. Emacs must be built with dynamic
modules, and =vterm-module.so= must compile; the first launch can build it with
=cmake=, =make=, and a C compiler, or use your distribution's libvterm. No shell
starts at startup.

| Keys            | Action                                                       |
|-----------------+--------------------------------------------------------------|
| SPC o t         | Toggle the workspace vterm popup at the project root         |
| SPC o T         | Open a terminal in the current window at the project root    |
| C-u SPC o t / T | Recreate the popup / use =default-directory= instead          |

The popup lives at the bottom of the frame (25%) and is scoped to the current
Perspective workspace. Both commands export the project root as =PROOT=. For
Tramp buffers the terminal logs in with the connection method and changes to the
remote directory. Following Doom's terminal module: exiting kills the buffer,
scrollback is 5000 lines, the modeline is hidden, killing the terminal does not
ask about running processes, and horizontal scrolling is disabled.

retains save/running-process prompts. Project EditorConfig may explicitly request
cleanup. Runtime metadata reduces friction, but is not a privacy boundary.

* Org planning and knowledge

** Storage and activation

Default layout (created only as captures need it):
#+begin_example
~/org/
  personal/{inbox,tasks}.org
  work/{inbox,tasks}.org
  roam/
    personal/{topics,ideas,projects,references,vocabulary,daily,reviews}/
    work/{topics,ideas,projects,references,vocabulary,daily,reviews}/
    general/{topics,ideas,projects,references,vocabulary,daily,reviews}/
#+end_example

One org-roam graph indexes all three domains in =~/org/roam=. Nothing migrates
existing notes/IDs. Unknown-layout legacy nodes are accessible with all-domain
lookup. Ordinary task files stay outside roam. Project tasks live inside their
project notes, not duplicated into daily files. TODOs written in =daily/= notes
are agenda files too, so a dated task can be captured where it is discussed.
Add existing other task files to =et/org-extra-agenda-files=; these appear in the
all-domain agenda. Emacs lock files (=.#*=) and autosave files (=#*#=) are ignored.

Roam completion shows file nodes by title and heading nodes by their full path:
=Document title -> Heading -> Subheading=. Ancestors need not have IDs. This
applies to both =et/roam-find= and =org-roam-node-find=; aliases remain searchable.
Only the completion labels change, not note contents, IDs or link descriptions.

Set a workspace's default with =SPC n D=. A domain-specific note overrides that
default. The default can be reset after restoring a session; it is not serialized
with layouts. Scoped lookup includes the current domain plus general. Uppercase
=SPC n r F/I/S= finds/inserts/searches all domains. =SPC u= supplies a prefix
argument to the next command (Evil reserves =C-u= for scrolling). The database, graph,
backlinks and explicit links can cross domains: this is not confidentiality
enforcement. AI integration must not silently send work notes.

The index starts on the first roam command, not Emacs startup. SQLite support is
required. The local browser graph starts *only* with =SPC n r g=; it contains
all domains and opens loopback-only HTTP/WebSocket servers. Close/disable
=org-roam-ui-mode= to stop it. Never expose that server to an untrusted network.
Sync source notes/attachments with Syncthing if desired, not =.local/= or live
SQLite files. Each machine rebuilds its own index with =SPC n r u=.

Task capture keys: =pi= personal inbox, =pt= personal TODO, =ph= daily personal
habit, =wi= work inbox, =wt= work TODO, =j= task in an existing project note.

Python, JavaScript, TypeScript (including TSX), C, C++, YAML, Java, SQL, YARA,

(Projectile) runs any command you prefer. YARA rules are not run against samples
on save. SQL does not connect to a database on opening a file. Schema-aware
Compose diagnostics require deliberate YAML-server schema configuration; plain
YAML syntax support alone is not a guarantee of Compose schema validation.

** Debugging with Dape

=Dape= is installed through =et/install-packages= and integrates with compilation
and source buffers. =SPC m D s= starts a session after checking Python's
debug adapter; a missing =debugpy= gives an actionable error instead of a
session that cannot connect. Dape launches debugpy on =127.0.0.1= so it does not
depend on how =localhost= resolves. =SPC m D b= marks or unmarks a breakpoint,
=SPC m D e= enables or disables it in place, and =SPC m D B= removes all
breakpoints. =SPC m D l/E/h/F= add log, conditional, hit-count, and function
breakpoints. =SPC m D c/n/i/o= continue and step, =SPC m D r= opens the REPL,
and =SPC m D q= quits. A project's =.dir-locals.el= can seed the adapter with
=dape-command=. Launching a debugger never happens just by opening or saving a
file.

A breakpoint can run code when hit. With point on an existing breakpoint,
=SPC m D a= sets a debuggee expression (evaluated in the stopped frame's
language), an Emacs Lisp expression, a shell command, or a script file.
Scripts are run with an interpreter inferred from the extension (Python,
JavaScript/TypeScript, shell, Emacs Lisp, Ruby, or Java) from the project root.
=SPC m D A= clears the action. Actions last for the current session and fire
from =dape-stopped-hook= only for a breakpoint stop at that file and line.

Dape uses adapters installed separately: =debugpy= for Python, =js-debug= for
JavaScript/TypeScript, =jdtls= with the java-debug plugin for Java, and =gdb=
(14.1 or newer) or =lldb-dap= for C/C++. For the Python example, install
=debugpy= in the interpreter Dape will use, or select a virtualenv containing it
with =SPC m v= before starting. The C/C++ examples compile with a Makefile
before launching and expose =compile_flags.txt= to clangd.

A local =examples/= directory (ignored by Git) contains disposable programs for
every supported language. The debug-capable examples are Python, JavaScript,
TypeScript, Java, C and C++; YAML, SQL, YARA, Dockerfile, Compose, TSX, Bash and
JSON exercise editing, LSP, tree-sitter and compilation only. Each example has
its own =.projectile= marker and Dape configuration where applicable.

** Installing tools separately

Use the package/environment manager you trust; these are examples, not commands
the configuration executes. Server versions must support your Node/JDK runtime.

#+begin_src sh
# Example Node-based servers (run yourself if desired):
npm install -g typescript typescript-language-server yaml-language-server dockerfile-language-server-nodejs
# Example Python tooling in a chosen development environment:
python -m pip install basedpyright ruff pytest debugpy
# JS/TS project-local test runner and formatter (run in the project):
npm install --save-dev vitest prettier   # or: jest
# C/C++ tooling (distribution packages vary):
# clangd, gdb >= 14.1 or lldb-dap, clang-format
# Node debug adapter for Dape: unpack Microsoft's js-debug release where Dape
# expects it. Java debugging requires jdtls plus Microsoft's java-debug plugin.
#+end_src

=basedpyright-langserver= is the preferred Python server; =pytest=, =debugpy=,
and =ruff= drive =SPC m t/T/u=, Dape, and =SPC m F= respectively. For JS/TS,
install =jest= or =vitest= (project-local =devDependencies=) plus =prettier= for
=SPC m F= and the js-debug adapter for Dape. Install JDT LS, sqls and yr-ls using
their supported distribution instructions; check runtime requirements. Ensure
each server/runner executable is visible in Emacs's PATH (or the selected venv /
project =node_modules/.bin=), not just a shell.

Python buffers automatically use the first usable virtualenv found in this
order: =.venv= beside the current file, then =.venv=, =venv=, =env=,
=.virtualenv=, or =virtualenv= at the project root, then =VIRTUAL_ENV=. If none
is found, Emacs asks once per project whether to choose one; =SPC m v= remains
available for an explicit selection. The choice updates PATH, =exec-path=,
=VIRTUAL_ENV=, =python-shell-interpreter=, and
=python-shell-virtualenv-root= *for the buffer*. The REPL uses the venv's
=ipython3= with =--simple-prompt= when present, otherwise the venv's =python=.
New Python buffers in the same project reuse an explicitly chosen environment;
already-open buffers keep their local state. The selected environment is
propagated to the Eglot server process through =VIRTUAL_ENV=, so basedpyright
analyses against that venv. Restart already-running Eglot/REPL processes after
changing it. Invoking =SPC m l=, a test command, or =SPC m F= in a local JS/TS
project opts into that project's =node_modules/.bin=, so only use it in trusted
projects. Repeated selection replaces rather than stacks paths.

** Docker and Compose

=SPC p D= opens Docker management. Docker CLI, daemon access and the Compose
plugin are external requirements; opening a Dockerfile/Compose file does not
contact the daemon. =SPC m V= runs only:
#+begin_src sh
docker compose -f /path/to/compose.yml config --quiet
#+end_src
It asks to save dirty buffers, quotes the filename, refuses remote file paths,
does not deploy/build/prune, and avoids printing expanded secrets. Compose may
still read environment files. Docker management operations are explicitly user
initiated and can be destructive; inspect commands before running them.

Docker CLI contexts or =DOCKER_HOST= can select an SSH endpoint; this config
does not change contexts. Remote file editing, remote Docker control and
development *inside* remote containers remain different workflows. Configure
remote server/interpreter paths and container path translation deliberately;
they have not been verified end-to-end against your hosts yet.
