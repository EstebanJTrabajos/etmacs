#+title: Etmacs
#+options: toc:2

A personal, literate Emacs configuration—not a Doom or Prelude clone. Includes
Evil, discoverable leader keys, completion, Projectile/Perspective workspaces,
Treemacs, Git tools, conservative editing defaults, and Org/roam workflows.
The source of truth and package rationales are in [[file:config.org][config.org]]. Maintained project
documentation uses Org format. Old session/planning artifacts are not runtime
dependencies and are not part of the proposed configuration commit.

* Try without replacing Doom

Requires Emacs 31.1+ with SQLite support. Run from this repository in a new
instance, not an existing Doom server client. Nothing migrates existing notes.

1. Generate the Lisp (also provided alongside its source):
   #+begin_src sh
   emacs -Q --batch --load scripts/tangle.el
   #+end_src
2. Explicitly install third-party packages and dependencies from GNU ELPA,
   NonGNU ELPA and MELPA. This downloads and executes package code:
   #+begin_src sh
   emacs -Q --batch --load init.el --funcall et/install-packages
   #+end_src
   Or start Emacs and run =M-x et/install-packages=, then restart. Normal
   startup never refreshes archives, installs packages, or starts a graph server.
3. Start the configuration:
   #+begin_src sh
   emacs --init-directory "$PWD" --debug-init
   #+end_src
   For terminal Emacs:
   #+begin_src sh
   emacs -nw --init-directory "$PWD" --debug-init
   #+end_src

Runtime packages and state live in ignored =.local/=. Native caches and editor
locks are not source. Packages are not version-locked; this is not a claim of
fully reproducible builds. =doom-conf/= is preserved as reference material.

* Editing and local settings

Edit =config.org=, run =M-x et/tangle-config=, and restart. Do not edit generated
=early-init.el=, =init.el= or =lisp/*.el= directly. There is no auto-tangle hook
on arbitrary Org files.

Optional =.local/settings.el= loads before modules. Set =et/notes-directory=,
=et/roam-directory=, =et/default-theme=, =et/bibliography-files=, or
=et/org-extra-agenda-files= there; not every core setting is an override API.
Credentials belong in =auth-source=, normally =~/.authinfo.gpg=, not this repo.
Customize writes to =.local/custom.el= but does not automatically load it;
promote intentional shared settings into the literate source.

Custom functions *and variables* use =et/=. File and feature names retain =et-=
(for example, =et-core.el=). Update any old =et-notes-directory= or
=et-default-theme= local overrides. Restart after renaming, not hot-reloading.

* Core keys and completion

| Keys                        | Action                                    |
|-----------------------------+-------------------------------------------|
| SPC SPC                     | Commands                                  |
| SPC f f / SPC f s / SPC f c | Find file / save / open config            |
| SPC b b / SPC b B           | Workspace buffers / all buffers           |
| SPC w v / SPC w s           | Split right / below                       |
| SPC w h/j/k/l               | Move between windows                      |
| SPC w u / SPC w r           | Winner layout undo / redo                 |
| SPC s / SPC /               | Buffer search / project-directory ripgrep |
| SPC t t                     | Theme picker with live preview            |

=SPC= is a leader in Evil normal/visual/motion states; ordinary Space inserts
spaces in insert state. =C-c SPC= is the alternative leader. Which Key groups
are labelled files, buffers, windows, projects, notes, git, help, themes,
workspaces, jump, edit and mode commands—not just "prefix".

Vertico handles minibuffer completion; Corfu handles in-buffer CAPFs. They do
not compete. Company/Cape are not installed without a specific need. Try Lisp
completion by typing =(messag= and pressing =C-M-i=. =TAB=/=S-TAB= move, =RET=
accepts a selected candidate, =C-g= dismisses. Automatic completion begins after
three characters; CAPFs may execute Lisp, so use care with untrusted code.

GUI Vertico menus float. Terminal frames use normal minibuffer rendering;
Corfu uses supported child frames or the built-in completion fallback. In the
theme picker, =C-n=/=C-p= preview, =RET= accepts, and =C-g= restores the previous
theme. Only trusted installed theme code should be previewed. Selection is
session-only; change =et/default-theme= for a persistent default.

* Projects, workspaces and windows

Projectile owns project roots/files/build/test commands; Perspective owns
workspace buffers and layouts. Same-basename projects receive distinct
=name#hash= workspaces. This is organizational isolation, not a sandbox: an
explicit file open may share a buffer between workspaces.

| Keys                    | Action                                                 |
|-------------------------+--------------------------------------------------------|
| SPC p a / SPC p p       | Register / switch project                              |
| SPC p w                 | Activate current project's workspace                   |
| SPC p f / SPC p s       | Project files / Consult project search                 |
| SPC p c / SPC p t       | Build / test (project commands may need configuration) |
| SPC TAB . / SPC TAB TAB | Choose / previous workspace                            |
| SPC TAB a / SPC TAB d   | Add / forget a buffer, without deleting its file       |
| SPC TAB S / SPC TAB L   | Explicit session save / restore                        |
| SPC e / SPC p e         | Toggle tree / display only the current project in tree |

Discovery is explicit, not a recursive startup scan. Treemacs uses Evil
bindings and Perspective scopes. Help opens right, compilation/warnings below;
=q= dismisses help/compilation. No additional pop-up framework is needed.

Session save/restore is *manual*. Local files and Dired layouts are supported;
remote files, tree buffers, unsaved buffer contents, terminals and LSP processes
are not restored. Unsupported windows become scratch windows. Restore only
trusted local state: opening files can invoke their mode hooks. Reconnect remote
tools deliberately. No automatic exit save can overwrite a good saved session
with a short empty session. Do not enable desktop restoration over these layouts.

We adopt capabilities from [[https://github.com/bbatsov/prelude][Prelude]], not its startup framework or global keymap.

| Source TODO/FIXME markers                               | hl-todo, not an alternative task database                        |
| Git operations/change markers/history                   | Magit, diff-hl, git-timemachine, git-modes                       |

| Keys                                  | Action                                                          |
|---------------------------------------+-----------------------------------------------------------------|
| SPC j j / SPC j w / SPC j l           | Two-character / word / line jump                                |
| SPC w w                               | Ace Window; existing directional bindings and C-x o stay intact |
| SPC c e / SPC c E                     | Expand / contract selection                                     |
| SPC c o/O / SPC c d                   | Open line below/above / duplicate line or region                |
| SPC f R / SPC f r                     | Explicit file+buffer rename / global recent files               |
| SPC g s / SPC g v                     | Magit status / built-in VC                                      |

Intentionally not enabled: super-save, midnight cleanup, persisted kill rings,
global whitespace cleanup or format-on-save, pasted-text reindentation,
automatic chmod, undo-tree, alternate completion frameworks, or Flycheck/Eglot
bridges. Recursive Dired operations retain top-level confirmation; compilation
retains save/running-process prompts. Project EditorConfig may explicitly request
cleanup. Runtime metadata reduces friction, but is not a privacy boundary.

* Org planning and knowledge

** Storage and activation

Default layout (created only as captures need it):
#+begin_example
~/org/
  personal/{inbox,tasks}.org
  work/{inbox,tasks}.org
  roam/
    personal/{topics,ideas,projects,references,vocabulary,daily,reviews}/
    work/{topics,ideas,projects,references,vocabulary,daily,reviews}/
    general/{topics,ideas,projects,references,vocabulary,daily,reviews}/
#+end_example

One org-roam graph indexes all three domains in =~/org/roam=. Nothing migrates
existing notes/IDs. Unknown-layout legacy nodes are accessible with all-domain
lookup. Ordinary task files stay outside roam. Project tasks live inside their
project notes, not duplicated into daily files. Add existing other task files
to =et/org-extra-agenda-files=; these appear in the all-domain agenda.

Roam completion shows file nodes by title and heading nodes by their full path:
=Document title -> Heading -> Subheading=. Ancestors need not have IDs. This
applies to both =et/roam-find= and =org-roam-node-find=; aliases remain searchable.
Only the completion labels change, not note contents, IDs or link descriptions.

Set a workspace's default with =SPC n D=. A domain-specific note overrides that
default. The default can be reset after restoring a session; it is not serialized
with layouts. Scoped lookup includes the current domain plus general. Uppercase
=SPC n r F/I/S= finds/inserts/searches all domains. =SPC u= supplies a prefix
argument to the next command (Evil reserves =C-u= for scrolling). The database, graph,
backlinks and explicit links can cross domains: this is not confidentiality
enforcement. AI integration must not silently send work notes.

The index starts on the first roam command, not Emacs startup. SQLite support is
required. The local browser graph starts *only* with =SPC n r g=; it contains
all domains and opens loopback-only HTTP/WebSocket servers. Close/disable
=org-roam-ui-mode= to stop it. Never expose that server to an untrusted network.
Sync source notes/attachments with Syncthing if desired, not =.local/= or live
SQLite files. Each machine rebuilds its own index with =SPC n r u=.

** Capture and daily use

| Keys                  | Action                                                             |
|-----------------------+--------------------------------------------------------------------|
| SPC n c / C-c c       | Task/inbox capture menu                                            |
| SPC n a / C-c a       | Choose agenda domain and open daily dashboard                      |
| SPC n D               | Set workspace default domain                                       |
| SPC n d               | Browse the existing Org root                                       |
| SPC n r c             | Choose domain, title, then a roam note template                    |
| SPC n r f / SPC n r i | Find note / insert ID link; uppercase F/I include all domains      |
| SPC n r s / SPC n r S | Scoped / all-domain full-text search                               |
| SPC n r d             | Today's journal/log/meeting; SPC u then SPC n r d chooses a domain |
| SPC n r w             | Weekly review linking seven dailies, without creating missing days |
| SPC n r b / a / t     | Backlinks / add alias / add subject tag                            |
| SPC n r g / u         | Explicit graph / rebuild local index                               |

Task capture keys: =pi= personal inbox, =pt= personal TODO, =ph= daily personal
habit, =wi= work inbox, =wt= work TODO, =j= task in an existing project note.
Choose/create a project note first via roam template =p=. Project capture asks
for an existing project in the current/shared domain. Plain TODOs have no
invented deadline/schedule; habit captures supply an editable daily repeater.
Finalize with =C-c C-c=; cancel with =C-c C-k=.

Roam template keys: =n= topic, =i= idea, =p= project, =r= reference, =v=
vocabulary. References store a URL or =cite:key= in indexed =ROAM_REFS= metadata.
Aliases and
tags are stored in the note, not a competing metadata system.

Daily template keys: =j= journal, =l= work log, =m= meeting. All entries for a
domain/date share one file. Work logs link to the actively clocked task via
Org's clock link; they do not create duplicate clock records. Clock/pomodoro
the real task. Vocabulary notes contain a drill-tagged question and Answer
heading; Arabic editing/bidi is preserved. Multilingual spelling is a later stage.

Agenda views include general projects plus the chosen personal/work domain, or
all domains. Only designated project directories are scanned. States are TODO,
NEXT, WAIT, DONE and CANCELLED; completion/wait logging lives in LOGBOOK drawers.
Use Org repeaters for recurring tasks, and the habit STYLE property for habits.

** Org-local commands, research and export

In Org buffers =SPC m= offers:
| Key                   | Action                                             |
|-----------------------+----------------------------------------------------|
| c / a / t             | Capture / agenda / TODO state                      |
| s / d / r             | Schedule / deadline / refile                       |
| i / l                 | Create ID / store link                             |
| k / K / p             | Clock in / out / Pomodoro                          |
| F f / F t / F a       | Drill file / subtree / resume                      |
| C                     | Insert citation through Citar                      |
| b / T                 | Execute source block / explicitly tangle this file |
| e e                   | Org export dispatcher                              |
| e h / e p / e d / e H | HTML / PDF / DOCX / Hugo                           |

Org, habits, agenda, capture, clocks, Babel and exporters are built in.
=org-roam= adds the linked-note index; =org-roam-ui= adds the browser graph.
=org-pomodoro= adds focus cycles and =org-drill= spaced repetition. =citar=
provides reference insertion/opening over Org Cite and your own BibTeX files;
set =et/bibliography-files= before startup. Zotero can maintain those files but
is not mandatory. PDF viewing initially uses Emacs's available built-in viewer;
pdf-tools/annotation integrations can be added separately.

HTML uses Org; PDF uses Org's LaTeX exporter and an external TeX toolchain.
HTML source blocks fall back to plain text if optional =htmlize= is absent.
=ox-pandoc= + external Pandoc supply DOCX. =ox-hugo= exports posts/subtrees;
set =#+hugo_base_dir:= and an appropriate section/export filename in your
document. Citation insertion works independently of export: bibliography
formatting requires the export-specific processor/style/toolchain to be chosen
and verified. Do not assume one citation setup works identically in all formats.

Babel enables Emacs Lisp, Python, shell, SQL, JavaScript and restclient when
its packages are installed. =restclient= / =ob-restclient= supply HTTP blocks.
Execution confirmation remains enabled; exporting does not execute blocks.
External interpreters/services remain your responsibility. Do not disable
confirmation globally or trust third-party literate files automatically.

* Languages, LSP and Docker

Python, JavaScript, TypeScript (including TSX), YAML, Java, SQL, YARA,
Dockerfiles and Docker Compose now have editing support. =lisp/et-dev.el= is
generated from the development section of =config.org=.

The built-in Eglot/Flymake/Xref/Eldoc stack supplies LSP, diagnostics, navigation
and documentation. Corfu displays completion; Vertico still handles prompts.
Servers are *explicitly started*, not launched by opening or saving files.
No server binaries, grammars, formatter tools or test runners are auto-installed.

| Language   | Mode choice                                                       | External server                                                  |
|------------+-------------------------------------------------------------------+------------------------------------------------------------------|
| Python     | Built-in python-mode, or python-ts-mode with an installed grammar | basedpyright-langserver (preferred); pyright/pylsp fall back |
| JavaScript | Built-in js-mode / js-ts-mode                                     | typescript-language-server --stdio                               |
| TypeScript | typescript-mode; built-in TS modes when grammars are ready        | typescript-language-server --stdio                               |
| TSX        | web-mode fallback; tsx-ts-mode with installed grammars            | Same TypeScript server                                           |
| YAML       | yaml-mode; built-in yaml-ts-mode with grammar                     | yaml-language-server --stdio                                     |
| Java       | Built-in java-mode / java-ts-mode                                 | jdtls with a compatible JDK, or java-language-server             |
| SQL        | Built-in sql-mode and optional sql.el REPL                        | sqls; dialect/connection setup remains explicit                  |
| YARA       | yara-mode (.yar/.yara)                                            | yr-ls via Emacs 31's Eglot mapping                               |
| Dockerfile | dockerfile-mode / dockerfile-ts-mode                              | docker-langserver --stdio                                        |
| Compose    | Small YAML-derived et/compose-mode                                | yaml-language-server --stdio                                     |

Package reasons: TypeScript, YAML, YARA and Dockerfile modes fill built-in
fallback gaps without requiring native grammar compilation; web-mode handles
TSX without a grammar. =docker= is the container-management interface. The old
=docker-compose-mode= is unavailable from the configured archives, so Compose
uses a small derived YAML mode instead of another bootstrap system. It detects
=compose.yml=, =compose.yaml=, =docker-compose.yml= and their dotted variants.
Dockerfile variants such as =Dockerfile.dev= and =*.dockerfile= are recognized.

In these buffers, =SPC m= supplies:
| Key   | Action                                                          |
|-------+-----------------------------------------------------------------|
| l / q | Start Eglot / shut down the current project's server            |
| d / R | Definition / references                                         |
| r / a | Rename symbol / code actions                                    |
| h     | Eldoc documentation buffer                                      |
| e / E | Buffer / project Flymake diagnostics                            |
| n / p | Next / previous diagnostic                                      |
| f     | LSP formatting (region if active, otherwise buffer)             |
| F     | Standalone formatting (Ruff / Prettier)                         |
| c / C | Projectile build / arbitrary test command                       |
| t / T | Test project / file                                             |
| u     | Test the test at point                                          |
| v     | Choose Python virtualenv directory (Python buffers only)        |
| V     | Validate saved local Compose file (Compose buffers only)        |

No format-on-save or test-on-save. =SPC m f= formats through the connected LSP
server if it advertises the capability. =SPC m F= runs a standalone formatter:
Ruff (=ruff format=) for Python and Prettier (=prettier --write=) for JS/TS,
refusing unsaved buffers and reloading only on success; a missing formatter is a
clear error, never an auto-install.

=SPC m t= runs the project's test suite, =SPC m T= the current file, and
=SPC m u= the test at point. Python uses =python -m pytest= (the selected venv's
interpreter); JS/TS detects =vitest= or =jest= from =package.json= and falls back
to =npm test= for the whole suite. Results appear in a compilation buffer. No
pytest/Jest/Vitest choice is silently imposed beyond these defaults; =SPC m c=
(Projectile) runs any command you prefer. YARA rules are not run against samples
on save. SQL does not connect to a database on opening a file. Schema-aware
Compose diagnostics require deliberate YAML-server schema configuration; plain
YAML syntax support alone is not a guarantee of Compose schema validation.

** Installing tools separately

Use the package/environment manager you trust; these are examples, not commands
the configuration executes. Server versions must support your Node/JDK runtime.

#+begin_src sh
# Example Node-based servers (run yourself if desired):
npm install -g typescript typescript-language-server yaml-language-server dockerfile-language-server-nodejs
# Example Python tooling in a chosen development environment:
python -m pip install basedpyright ruff pytest
# JS/TS project-local test runner and formatter (run in the project):
npm install --save-dev vitest prettier   # or: jest
#+end_src

=basedpyright-langserver= is the preferred Python server; =pytest= and =ruff=
drive =SPC m t/T/u= and =SPC m F= respectively. For JS/TS, install =jest= or
=vitest= (project-local =devDependencies=) plus =prettier= for =SPC m F=. Install
JDT LS, sqls and yr-ls using their supported distribution instructions; check
runtime requirements. Ensure each server/runner executable is visible in Emacs's
PATH (or the selected venv / project =node_modules/.bin=), not just a shell.

=SPC m v= selects an existing local virtualenv's =bin/python= and adjusts PATH
and =exec-path= *for this buffer*. It does not guess uv/Poetry/Conda layouts or
change all project buffers. The interactive Python REPL uses =ipython3= (with
=--simple-prompt=) when available, falling back to plain =python=. The selected
environment is propagated to the Eglot
server process via =VIRTUAL_ENV=, so basedpyright analyses against that venv.
Select the environment before starting Eglot/REPL; restart already-running
processes after changing it. Invoking =SPC m l=, a test command, or =SPC m F= in
a local JS/TS project opts into that project's =node_modules/.bin=, so only use
it in trusted projects. Repeated selection replaces rather than stacks paths.
Other project buffers may need the same selection explicitly.

** Docker and Compose

=SPC p D= opens Docker management. Docker CLI, daemon access and the Compose
plugin are external requirements; opening a Dockerfile/Compose file does not
contact the daemon. =SPC m V= runs only:
#+begin_src sh
docker compose -f /path/to/compose.yml config --quiet
#+end_src
It asks to save dirty buffers, quotes the filename, refuses remote file paths,
does not deploy/build/prune, and avoids printing expanded secrets. Compose may
still read environment files. Docker management operations are explicitly user
initiated and can be destructive; inspect commands before running them.

Docker CLI contexts or =DOCKER_HOST= can select an SSH endpoint; this config
does not change contexts. Remote file editing, remote Docker control and
development *inside* remote containers remain different workflows. Configure
remote server/interpreter paths and container path translation deliberately;
they have not been verified end-to-end against your hosts yet.

** Verify language workflows

1. Open disposable .py/.js/.ts/.tsx/.yaml/.java/.sql/.yar files, Dockerfile,
   and compose.yml. Check modes, syntax/indentation, Corfu and =SPC m= bindings.
   Repeat without grammars installed to verify classic-mode fallbacks.
2. Install one server first (Python or TypeScript), start it with =SPC m l=.
   Trigger completion; introduce a type error; inspect Flymake; navigate to
   definition/references; rename a symbol. Check unsupported-server errors are
   clear. =SPC m q= must stop it. No connection should start on file open alone.
3. Request formatting only when the server supports it; verify ordinary saves do
   not format. Run =SPC m F= in Python/JS files with =ruff=/=prettier= installed;
   confirm unsaved buffers are refused and the buffer reloads on success.
4. Run =SPC m t/T/u= in a Python project (virtualenv selected, =pytest= installed)
   and a JS/TS project (=jest= or =vitest= in =devDependencies=); check the
   project/file/test-at-point commands and their compilation output. Verify the
   =SPC m t= -> =npm test= fallback when no runner is detected.
5. Select two Python environments and check buffer-local interpreter/PATH, that a
   restarted Eglot uses the selected venv, and process restart behavior. Test
   Node tools in a trusted local project.
6. Validate a disposable Compose file, confirm errors go to compilation output,
   and ensure no containers were started. Test Docker management separately.

Automated tests cover mode/filename detection, no automatic servers, command
bindings, isolated environments and their propagation to the server process,
basedpyright preference, pytest/Jest/Vitest command construction and runner
detection, standalone formatting and reload, Compose validation/cancellation,
and a real Eglot JSON-RPC connection to a deterministic test fixture for CAPF,
Flymake, Xref and formatting. This fixture does *not* verify production
language-server behavior. No production server is installed on this development
host yet.

* External dependencies and remaining stages

Git and ripgrep are used by project/Git/search commands. On Arch/Ubuntu the
search package is =ripgrep=. PDF needs TeX; DOCX needs Pandoc. org-roam needs
built-in SQLite support. No system packages, language servers, dictionaries,
or tree-sitter grammars are silently installed. Babel needs the corresponding
interpreter/database/HTTP service for the blocks you execute.

For PDF, having =pdflatex= and =latexmk= executables is not enough: the TeX
distribution's formats and LaTeX packages must also be installed/configured.
An error about missing =pdflatex.fmt= is a system TeX setup problem, not an Org
export setting. Fix that distribution setup before verifying PDF output.

Production-server tuning, remote/container development, vterm, AI,
spelling/grammar, deeper citation/PDF workflows and optional Forge remain
separate stages. Do not load another completion or diagnostic framework globally
over the current one without a concrete reason.

* Verification

Automated checks (offline; package-specific checks skip until installation):
#+begin_src sh
emacs -Q --batch --load tests/et-core-tests.el --funcall ert-run-tests-batch-and-exit
#+end_src

Tests use disposable notes/repositories, not your real vault. They cover source
tangling, startup/no installation, labels through both leaders, workspace
scoping/layouts and fresh-process restoration, safe persistence, completion,
EditorConfig, structural edits, conservative saves, pop-ups, and Org workflows.
They do not replace real keyboard/rendering/server/export checks.

Manual acceptance checklist:
1. Restart offline; check Evil, labels, GUI floating completion and terminal
   fallback. Preview/cancel themes repeatedly; =custom-enabled-themes= should
   contain only the selected theme.
2. Register two disposable projects; switch between them, split their layouts,
   check scoped/all buffer pickers and independent trees, then save/restart/load.
   Use =SPC w u= to test layout undo without crossing workspace layouts.
3. Try Avy/Ace Window, region expansion, explicit Crux helpers and Lisp
   slurp/barf. Verify EditorConfig, local auto-revert, Git markers and Magit.
   Ordinary buffer switches must not save, and saves must not trim unrelated
   trailing spaces. Check compilation ANSI colors and help placement.
4. Capture personal/work TODOs and a habit. Create a project note and capture
   its task; verify the right scoped/combined agenda and refile destinations.
   Complete a recurring task; verify its repeater and LOGBOOK behavior.
5. Create notes in two domains and general. Add aliases/tags, insert an ID
   link, view backlinks, compare scoped/all search, then rebuild the index.
   IDs and source notes must remain intact. Open the graph explicitly.
6. Capture two daily entries and a meeting. Clock a project task, make a work
   log, stop the clock, and inspect the daily link and original task's clock
   record. Drill a vocabulary note; verify Arabic editing/font fallback.
7. Insert/open a bibliography reference and export a disposable report to each
   required format with your installed tools. Verify citations/bibliographies
   separately in each output. Source blocks must not run during export; manual
   execution must still ask. Do not use sensitive real HTTP endpoints in tests.
